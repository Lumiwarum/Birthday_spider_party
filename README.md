# Паучья мультивселенная — Spider-Verse Birthday Metagame

Локальное приложение ведущего: 11 гостей, 11 порталов, 11 фигурок LEGO 71050.

## Запуск

- Разработка: открыть `index.html` в браузере (сервер не нужен).
- Один автономный файл: `python tools/build.py` → `dist/spiderverse-party.html` (CSS, JS, аватары и фото фигурок встроены).
- Экран для гостей: «Данные» → «Открыть экран гостей». Второе окно всегда в режиме демонстрации, обновляется само и показывает публичные объявления.

## Инструкция для ведущего

1. **Подготовка.** «Участники» → «Изменить»: имя, аватар, секретный персонаж (квест меняется вместе с ним). «Порталы» → случайная или ручная раскладка. «Награды» → при желании включите Раунд 3 и добавьте игры.
2. **«Начать вечеринку»** на панели: текущее расположение фиксируется как первоначальное (для «Возвращения домой»).
3. **После каждой игры** — «Награды» → «Записать итоги»: отметьте места (ничьи — одинаковое место), начисление одной операцией.
4. **Квесты.** Карточка участника → «Квест выполнен» (+3 RP, +3 EP, способность). У Майлза — «Украсть квест…». У Сан-Спайдер — «Подсказки о квестах».
5. **Покупка.** «Магазин» → «Купить» → игрок и цели → «Объявить». EP списываются сразу, открывается **окно реакции** («Реакции»): очередь желающих, «Сбой канона», дуэль Веб-Слингера. «Закрыть реакции и выполнить» применяет эффект и показывает приватный результат — прочитайте его игроку.
6. **Уникальные способности** — экран «Способности»: применение, чай Павитра, пара «Мэйдэй!» и повторы, ваучеры Сан-Спайдер.
7. **«Следующий раунд»** обновляет лимиты «раз в раунд» и снимает защиту Киборга. После последнего раунда открывается финальное окно (лимиты обновляются, защита Киборга остаётся).
8. **«Заморозить мультивселенную»** — дальше никаких покупок, способностей и перемещений. Публичная жеребьёвка разрешает равенство RP.
9. **«Финал»:** выбор батчей по порядку → тайные предпочтения → «Провести распределение» (жеребьёвки сохраняются) → «Подтвердить» → раскрытие.
10. **Ошибся?** Кнопка ручного отката в шапке или в журнале восстанавливает состояние до последнего действия. Это исправление ведущего, не игровая отмена.

Перед показом гостям переключитесь в «Демонстрацию» (выход — удержанием кнопки) или используйте отдельное окно гостей.

## Структура

```
index.html            подключает CSS и JS в нужном порядке
css/                  тема, компоненты, стили экранов (screens/game.css — механика)
js/core/              config (правила и константы), store (состояние, act(), откат, миграция),
                      selectors, utils, media, data-io (экспорт/импорт/сброс)
js/data/              abilities (12 покупных), unique (11 уникальных), иконки, аватары, фото фигурок
js/game/              info (распознавание и маскировки), moves (перемещения с защитой),
                      quests, actions (объявление → реакция → исполнение), rounds, final
js/ui/                компоненты, модальные окна, формы целей, объявления для гостей
js/screens/           экран = view-функция + свои обработчики
js/app.js             вкладки, render(), события, синхронизация окна гостей
```

## Как расширять

- Любое изменение — через `act(entry, mutate)`: снимок для отката + запись в журнал. `fail('…')` внутри mutate отменяет изменения.
- Способность — объект в `SHOP` / `UNIQUE` с `fields`, `validate`, `execute`. Эффект вызывается только после окна реакции.
- Тип события — строка в `EVENT_TYPES`; `pub` задаёт видимость в демонстрации.
